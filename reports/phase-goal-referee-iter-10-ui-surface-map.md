## Backend-Only Changes (No UI Impact)

- `_pool_strategy_trades`'s new `candidate` filter (rider 1, `apps/backend/app/research/referee_adjudicate.py`) — scopes evidence pooling to the exact `(strategy_id, profile)` a certificate is being minted for — no UI surface; the only caller path this protects (`certificate_mint` inside `run_evaluation_and_record`) still has zero production callers this era, so nothing an operator can click reaches it.
- Module docstring and `authorize_promotion` docstring cleanup (rider 2, same file) — dropped stale "unwired this iteration" language now that it is wired into `pnl_scan._promote` — comment-only text, no behavior or UI impact.
- `test_no_bypass_guard_can_fail_on_a_seeded_violation` refactor (rider 3, `apps/backend/tests/test_pnl_scan.py`) — makes a guard test exercise the real scan logic instead of a hand-typed string — test-only, no UI surface.
- Duplicate `S-5` assertion removed (rider 4, `apps/backend/tests/test_referee_registry.py`) — test-only cleanup, no behavior or UI change.
- Guard-test growth (`_PRICE_ARITHMETIC_FIELDS` in `test_desk_ui_guards.py`, `_EXPECTED_EFFECT_COUNT`/`_EXPECTED_INTERVAL_COUNT` in `test_desk_refresh_chain_guard.py`, `EXPECTED_TOOLS` in `test_mcp_server.py`, the `test_copy_discipline.py` lexicon check) — these are protective tests that verify the new UI surfaces above stay honest (no client-side arithmetic, no missing effect/interval accounting, correct tool count); they are not themselves a UI surface.
